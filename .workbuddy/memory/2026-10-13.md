## 排查：Api 未启动 Vue3 前端也能打开 http://localhost:9291/ui/#/

- 机制：`wwwroot/ui/` 不是源码目录，而是启动时从 `wwwroot/ui.zip` 解压生成的。
  - `MultiAgentDevelop.Extensions/ServiceExtensions/UiFilesZipSetup.cs`：`AddUiFilesZipSetup` 判断 `wwwroot/ui/index.html` 不存在则 `ZipFile.ExtractToDirectory(wwwroot/ui.zip, wwwroot)`；zip 顶层已是 `ui/`。
  - `MultiAgentDevelop.Api/Program.cs:54` 注册（builder 阶段，Build 之前，同步阻塞 IO）；`:165-166` `UseDefaultFiles`(index.html) + `UseStaticFiles` 托管 wwwroot。
  - `/ui/#/` 的 hash 段由浏览器处理，服务端只收到 `/ui/`，被 DefaultFiles 改写成 `/ui/index.html`。
- 关键事实：`wwwroot/ui/` 是**独立的 vue-cli/webpack 构建产物**（标题 blog.admin，chunk-xxxx 命名，index.html 2022-04-10），与仓库里的 `MultiAgentDevelop.Vue3`（vite + vue-router）**无关**。Vue3 走自己的 dev server，通过 `vite.config.ts` proxy 把 `/api` 转发到 9291。
- 工程约定：`.gitignore:357` 忽略 `MultiAgentDevelop.Api/wwwroot/ui/`；csproj 对 `wwwroot\ui\**` 做了 Compile/Content/EmbeddedResource/None 全 Remove，仅 `wwwroot\ui.zip` 设 `CopyToOutputDirectory=PreserveNewest`。即：**发布产物只带 ui.zip，不带解压后的 ui 目录**。
- 坑：解压触发条件只看 `ui/index.html` 是否存在 → ① 改了 ui.zip 不重启会一直用旧目录，必须先删 `wwwroot/ui`；② 目录存在但缺 index.html 时会重复解压并因目标非空抛 IOException 导致启动失败。
- 未改动任何代码，仅阅读排查。
