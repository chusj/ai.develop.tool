# 短信平台 · L2 横切规范

> 所有功能共用的一致性约定，避免在每个功能文档里重复描述。
> 本节已按 MultiAgentDevelop 实际框架校正（2026-10-13）。标「框架现状」的条目是项目既有实现，**直接复用，不要另起一套**。

## 1. 统一返回结构（框架现状，必须遵循）

全站 API 统一包装为 `MessageModel<T>`（`MultiAgentDevelop.Model/MessageModel.cs`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| status | int | HTTP 语义状态码，默认 200；失败时 500 |
| success | bool | 操作是否成功 |
| msg | string | 提示信息 |
| msgDev | string | 开发环境堆栈信息（仅 Development 环境填充） |
| response | T | 业务数据（泛型） |

Controller 继承 `BaseApiController`，**直接调用基类方法，不要手写 MessageModel**：

```csharp
return Success(data, "获取成功");            // MessageModel<T>
return SuccessPage(pageModel, "获取成功");   // MessageModel<PageModel<T>>
return Failed("参数不合法");                 // MessageModel<string>，status = 500
return Failed<string>("删除失败");
```

- 前端 `BaseResponse<T>`（`src/utils/axiosInstance.ts`）已与该结构对齐。
- 字段名**原样序列化**（Newtonsoft `DefaultContractResolver`，不做 camelCase 转换）→ 前端 TS 接口必须照抄后端属性名大小写。

## 2. 统一异常处理（框架现状）

- 全局过滤器 `Api/Filter/GlobalExceptionsFilter.cs` 捕获未处理异常，统一返回 `MessageModel { status = 500, msg = 异常消息 }`，同时写错误日志、推送 SignalR 日志。
- ⚠️ **框架内不存在 `BusinessException` 类型**（已核实）。业务校验失败请**直接返回 `Failed("提示语")`**，不要为了抛异常而新增异常类型；确需抛出中断流程的，使用框架既有异常类型，由全局过滤器兜底。
- 第三方通道异常统一包装为 `SmsSendException`，**消息中不得包含 AccessKey / AccessSecret 等敏感信息**。

## 3. 权限模型（框架现状）

- RBAC 链路：`SysUserInfo` → `UserRole` → `Role` → `RoleModulePermission` → `Modules`（接口模块）/ `Permission`（菜单与按钮）。
- Controller 标注 `[Authorize(Permissions.Name)]`；权限点校验在 `PermissionHandler` + `Api/Filter/GlobalAuthorizeFilter.cs`。
- 新增 Controller 后需在「菜单权限管理」中登记对应 `Modules` / `Permission`，否则授权校验不通过。
- 短信发送接口需校验：账号是否有权限 + 余额是否充足。
- 记录查询按数据权限过滤（只能看权限范围内的账号）。

## 4. 审计字段（框架现状）

- 业务实体继承 `BaseEntity`（`Models/RootTkey/BaseEntity.cs`），自动获得：
  `Id`(long) / `Enabled` / `IsDeleted` / `IsInternal` / `CreateId` / `CreateBy` / `CreateTime` / `ModifyId` / `ModifyBy` / `ModifyTime` / `Version`。
- **逻辑删除统一 `IsDeleted`**（C# `bool`，Oracle `NUMBER(1)`），不做物理删除。
- ⚠️ `RepositorySetting` 的全局软删除过滤器**只对 `BaseEntity` 子类生效**：
  - 继承 `BaseEntity` 的实体，查询自动附加 `IsDeleted != true`；
  - 像 `Role` / `Modules` / `Permission` 那样直接继承 `RootEntityTkey` 并手写 `IsDeleted` 的实体**不走全局过滤**，须在查询里显式写条件。
  - **短信平台业务表一律继承 `BaseEntity`。**
- 创建/修改人字段在 Controller 中显式赋值（注入 `IUser`，位于 `Common/HttpContextUser/IUser.cs`）：

```csharp
entity.CreateId = _user.ID;
entity.CreateBy = _user.Name;
```

## 5. 日志规范

- 操作类日志统一走框架操作日志组件（`OperateLog` + AOP，见 `Common/DB/Aop/`），**不单独开发**。
- 发送动作必须落 `sms_send_record`，无论成功失败。
- 充值动作必须落 `sms_recharge`，且加锁保证余额一致性。
- 应用日志用 `ILogger<T>` / Serilog，禁止用 `Console.WriteLine` 充当业务日志。

## 6. 通用约定

| 项 | 约定 |
| --- | --- |
| 分页请求 | `page`（默认 1）+ `intPageSize`（默认 20，上限 100）；框架另有 `PaginationModel`（`PageIndex` / `PageSize`），同一模块内保持一致即可 |
| 分页响应 | 统一 `PageModel<T>`：`page` / `pageCount` / `dataCount` / `PageSize` / `data` |
| 排序 | 框架查询方法直接传排序字符串，如 `" Id desc "` |
| 手机号校验 | 正则 `^1[3-9]\d{9}$` |
| 短信内容长度 | 单条 ≤ 500 字，超长拆分 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（Newtonsoft 全局配置，见 `AGENT.md`） |
| 长整型传输 | Int64 经 `NumberConverter` 序列化为**字符串**传给前端（防 JS 精度丢失）→ 前端主键字段类型写 `string` |
| 导出编码 | CSV 使用 UTF-8 BOM，防 Excel 乱码 |

## 7. 事务与并发

- 涉及金额 / 额度的操作必须显式事务，二选一：

```csharp
// 方式 A：SqlSugar 原生（BaseServices 暴露 Db）
var result = await Db.Ado.UseTranAsync(async () =>
{
    // 更新余额 + 写流水
});

// 方式 B：框架工作单元（Repository/UnitOfWorks/IUnitOfWorkManage）
using var uow = _unitOfWorkManage.CreateUnitOfWork();
// ... 操作后提交
```

- 余额变更使用行锁（Oracle `SELECT ... FOR UPDATE`）防止并发丢失更新。
- 批量发送需控制并发度，避免打爆第三方通道限流。
