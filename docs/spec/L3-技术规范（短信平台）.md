# 短信平台 · L3 技术规范

> 决定代码往哪写、怎么命名、用什么版本。喂给 Agent 时，这份与 L1、L2 一样属于「全局层」，应在功能文档之前提供。
> 已按 MultiAgentDevelop 实际工程校正（2026-10-13），技术栈与目录均已落地核对。

## 1. 技术栈（框架现状）

| 项 | 选型 |
| --- | --- |
| 运行时 | **.NET 8**（`Directory.Build.props` 统一 `net8.0` + `ImplicitUsings=enable`） |
| Web 框架 | **ASP.NET Core WebAPI**（非 MVC5 / WebApi2） |
| ORM | SqlSugarCore 5.1.4.158（CodeFirst + DbFirst） |
| IOC | Autofac（`Extensions/ServiceExtensions/AutofacModuleRegister.cs`） |
| 数据库 | Oracle |
| 前端 | Vue 3 + Vite + TypeScript + Element Plus + Pinia |
| 部署 | Kestrel / IIS（API 监听 9291） |

## 2. 工程分层（框架现状，按此放置代码）

```
MultiAgentDevelop.Api          // 接口层：Controllers、Filter、Program.cs、appsettings.json
MultiAgentDevelop.Extensions   // 启动装配：ServiceExtensions（Autofac / SqlSugar / JWT / ...）
MultiAgentDevelop.Services     // 业务实现：XxxServices
MultiAgentDevelop.IServices    // 业务契约：IXxxServices
MultiAgentDevelop.Repository   // 数据访问：BaseRepository、UnitOfWork、Mongo
MultiAgentDevelop.Model        // 实体（Models/）、DTO（ViewModels/）、枚举、分页、统一响应
MultiAgentDevelop.Common       // 工具、缓存、配置、数据库基础设施、加密、日志
MultiAgentDevelop.Tasks        // Quartz 任务与 HostedService
MultiAgentDevelop.Vue3         // 前端工程（页面 / 路由 / api 封装）
```

依赖方向：`Api → Extensions → Services → IServices → Repository → Common/Model`

**新增一个业务模块要动的位置**（短信平台按此清单施工）：

| 层 | 文件 | 说明 |
| --- | --- | --- |
| 实体 | `Model/Models/SmsAccount.cs` | 命名空间**必须精确等于** `MultiAgentDevelop.Model.Models` |
| 服务契约 | `IServices/ISmsAccountServices.cs` | 继承 `IBaseServices<SmsAccount>` |
| 服务实现 | `Services/SmsAccountServices.cs` | 继承 `BaseServices<SmsAccount>` |
| 控制器 | `Api/Controllers/SmsAccountController.cs` | 继承 `BaseApiController` |
| 前端接口 | `Vue3/src/api/smsAccountApi.ts` | 复用 `@/utils/axiosInstance` |
| 前端页面 | `Vue3/src/views/Sms/Account/` | 列表页 + 编辑弹窗 |

> **Service / Repository 不需要手工注册**：`AutofacModuleRegister` 加载 `MultiAgentDevelop.Services.dll` / `Repository.dll` 后 `RegisterAssemblyTypes().AsImplementedInterfaces()` 自动装配。但这两个 dll 缺失时启动会直接抛异常。
>
> **实体表会自动创建**：`Common/Seed/DBSeed.cs` 反射扫描命名空间为 `MultiAgentDevelop.Model.Models` 且不带 `[MultiTenant]` 的类执行 `CodeFirst.InitTables`——**只建不删**。命名空间放错的实体不会被建表；放对的查询 DTO 会被误建表，注意别把 DTO 放进该命名空间。

## 3. 命名规范

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 类 / 接口 | PascalCase，接口 I 前缀 | SmsAccountServices / ISmsProvider |
| 方法 | PascalCase（框架既有代码异步方法多不带 Async 后缀） | SaveAccount / QueryPage |
| 私有字段 | `_camelCase`，readonly | `_smsAccountServices` |
| 实体属性 | PascalCase | `AccountName` |
| 表名 / 列名 | snake_case，用特性**显式声明** | `sms_send_record` / `[SugarColumn(ColumnName = "send_status")]` |
| 路由 | `api/{Controller}` + 小写动作段 | `/api/SmsAccount/page` |
| DTO | 名词 + Dto / Request 后缀 | SmsAccountDto |
| 前端文件 | 页面目录 PascalCase；接口文件 camelCase + `Api.ts` | `views/Sms/Account/Index.vue`、`smsAccountApi.ts` |
| 前端类型 | TS 接口字段**照抄后端属性名大小写** | `Id: string`、`AccountName: string` |

## 4. 接口风格

⚠️ **两种风格并存，短信中台新模块一律用第 2 种**：

1. **框架自带 Controller**（Role / User / Module 等）：`[Route("api/[controller]/[action]")]` 动作式路由，如 `/api/Role/Get`、`/api/Role/Post`。
2. **短信中台新模块**（自 PRD-01 起约定）：`[Route("api/[controller]")]` + RESTful 风格，动作段并入路由：

| 动作 | 方法 | 路径示例 |
| --- | --- | --- |
| 分页查询 | GET | `/api/SmsAccount/page?page=1&intPageSize=20` |
| 详情 | GET | `/api/SmsAccount/{id}` |
| 新增 | POST | `/api/SmsAccount` |
| 修改 | PUT | `/api/SmsAccount` |
| 删除 | DELETE | `/api/SmsAccount/{id}` |
| 启停 | PATCH | `/api/SmsAccount/status/{id}/{status}` |
| 导出 | GET | `/api/SmsAccount/export` |

统一返回 `MessageModel`，详见 L2 §1。

## 6. 样板代码（照此风格）

```csharp
// Controller
[Route("api/[controller]")]
[ApiController]
[Authorize(Permissions.Name)]
public class SmsAccountController : BaseApiController
{
    private readonly ISmsAccountServices _smsAccountServices;
    private readonly IUser _user;

    public SmsAccountController(ISmsAccountServices smsAccountServices, IUser user)
    {
        _smsAccountServices = smsAccountServices;
        _user = user;
    }

    [HttpGet("page")]
    public async Task<MessageModel<PageModel<SmsAccount>>> GetPage(
        int page = 1, int intPageSize = 20, string accountName = "", int? status = null)
    {
        var data = await _smsAccountServices.QueryPage(
            a => a.IsDeleted != true && (string.IsNullOrEmpty(accountName) || a.AccountName.Contains(accountName)),
            page, intPageSize, " Id desc ");
        return Success(data, "获取成功");
    }
}

// Services
public class SmsAccountServices : BaseServices<SmsAccount>, ISmsAccountServices { }

// Entity（命名空间必须是 MultiAgentDevelop.Model.Models）
[SugarTable("sms_account", "短信账号表")]
public class SmsAccount : BaseEntity
{
    [SugarColumn(ColumnName = "account_name", Length = 64, IsNullable = false, ColumnDescription = "账号名称")]
    public string AccountName { get; set; }
}
```

## 7. 第三方通道抽象

- 统一接口 `ISmsProvider`：

| 方法 | 说明 |
| --- | --- |
| Send | 发送短信 |
| QueryBalance | 查询余额 |
| QueryStatus | 查询发送状态 |

- 各服务商实现：`AliyunSmsProvider` / `TencentSmsProvider` / `MengwangSmsProvider` / `HttpCustomSmsProvider`（对应 L1 的 `provider_type`）。
- 失败重试：最多 3 次，指数退避。
- 实现放 `MultiAgentDevelop.Services/Sms/Providers/`，由工厂按 `provider_type` 解析。

## 8. 配置管理

- **通道密钥加密存储**：入库前 AES 加密，接口一律返回掩码（PRD-01 R2）。AES 密钥与初始向量放 `appsettings.json`，通过 `AppSettings.app(...)` 读取——**禁止硬编码，禁止提交真实密钥**。
- 配置项集中管理：数据库配置表或配置文件，禁止散落硬编码。
- 涉及数据库 / 缓存 / 消息队列 / 注册中心时，先检查 `appsettings.json` 里的 `Enabled` 开关。
