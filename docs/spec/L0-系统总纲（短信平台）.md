# 短信平台 · L0 系统总纲

> 本文档是整套上下文清单的入口。喂给 Agent 开发时，务必先给 L0，再给 L1–L3，最后逐个给 L4 功能文档。

## 1. 系统定位

- **一句话描述**：统一封装第三方短信通道，为业务系统提供短信发送、充值、记录查询能力的中台服务。
- **不管的事**（AI建议）：不自建短信通道、不负责业务系统内的消息模板业务逻辑（模板由业务方传入或用平台管理）。

## 2. 系统边界

| 包含 | 不包含 |
| --- | --- |
| 短信账号管理、充值、发送、记录 | 具体业务场景的消息推送逻辑 |
| 对接多家短信服务商 | 自建运营商通道 |
| 余额/用量管控 | 计费结算系统 |

## 3. 功能清单与依赖

| 编号 | 功能模块 | 优先级 | 依赖 |
| --- | --- | --- | --- |
| F1 | 短信账号管理 | 高 | 无 |
| F2 | 短信充值 | 高 | F1 |
| F3 | 短信记录 | 高 | F1 |
| F4 | 短信模板管理（AI建议） | 中 | 无 |
| F5 | 发送统计/报表（AI建议） | 低 | F3 |

## 4. 术语表

| 术语 | 英文/字段 | 定义 |
| --- | --- | --- |
| 短信账号 | sms_account | 对接某服务商的一组配置（AccessKey 等） |
| 通道 | channel | 服务商维度，如 aliyun / tencent（AI建议） |
| 充值 | recharge | 向短信账号预存额度 |
| 发送记录 | sms_send_record | 每条短信的发送明细 |
| 签名 | sign | 短信签名，如「【XX公司】」（AI建议） |

## 5. 系统架构

- **分层**（AI建议）：Controller(WebApi) → Business → Business.SqlSugar → Oracle
- **第三方通道**（AI建议）：策略模式，ISmsProvider 接口 + 各家实现

## 6. 角色与权限

| 角色 | 权限范围 |
| --- | --- |
| 超级管理员 | 全部 |
| 短信管理员 | 账号/充值的增删改查 |
| 普通用户 | 仅查看自己的发送记录 |

## 7. 全局约定速览

- 所有跨功能的数据定义见 L1；横切规范见 L2；技术规范见 L3。
- 每个功能文档（L4）末尾必须带「依赖钩子」小节，用于串联上下文。
- 凡是标记「AI建议」的地方：采纳或改写均可，**不要留空**。
