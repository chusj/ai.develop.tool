# 短信平台 · L6 验收文档

> 定义「什么算做完」以及怎么验证。Agent 交付时以此为准。

## 1. 完成定义 DoD

- 接口联调通过（AI建议）。
- 单元测试覆盖核心逻辑（AI建议）。
- 关键异常场景有处理。
- 建表脚本齐全。
- 代码符合 L3 技术规范与 L2 横切规范。

## 2. 验收用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| T1 | 新增重复账号名 | 报错 |
| T2 | 充值后余额正确增加 | 余额 = before + amount |
| T3 | 并发充值 | 余额无丢失 |
| T4 | 发送成功落记录 | 记录状态 = 成功 |
| T5 | 发送失败落记录 + 原因 | 状态 = 失败，含 error_msg |
| T6 | 导出 CSV | 文件内容与列表一致 |
| T7 | 无权限用户查他人记录 | 拦截（AI建议） |
| T8 | 删除账号后查询记录 | 记录仍可查（快照保留） |

## 3. 部署说明

- Oracle 执行建表脚本。
- 配置文件配置通道密钥。
- WebApi 部署 IIS，配置应用池（AI建议）。

## 4. 环境依赖

| 项 | 要求 |
| --- | --- |
| 数据库 | Oracle 11g+ |
| 运行时 | .NET Framework 4.7.2 |
| Web 服务器 | IIS 7+ |
| 第三方 | 各短信服务商账号（AI建议） |
