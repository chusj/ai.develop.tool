# 短信平台 · L4 功能文档

> 本文档收录 3 个核心功能点（F1 账号管理 / F2 充值 / F3 记录），F4 模板管理、F5 统计报表为后续版本。
> 每个功能末尾的「依赖钩子」是让 Agent 串联上下文的关键，务必保留。实际开发时，可按需拆成独立文档。
>
> **口径已按 MultiAgentDevelop 实际代码校正（2026-10-13）**：接口路径、分页参数、字段名、路由风格均以本文件 + PRD-01 为准；数据定义只写在 L1，此处不重复。

## F0 · 短信模块公共约定（三个功能共同遵守）

- **路由**：`[Route("api/[controller]")]` + RESTful 风格的动作段，控制器名不带 `Sms` 前缀省略（如 `SmsAccountController` → `api/SmsAccount`）。框架自带的系统模块仍用 `api/[controller]/[action]` 动作式，两者并存，**新模块一律 RESTful**。
  > ⚠️ **集合级动作也必须带路径段**（`create` / `update` / `remove/{id}`），不要写成裸 `POST /api/SmsAccount`。原因：框架的「菜单同步」（`PermissionController.MigratePermission`）只登记 swagger 中控制器名后还有一段的接口，裸路径会被漏掉，导致非超级管理员角色鉴权 403。
- **分页参数**：查询串统一 `page`（默认 1）/ `intPageSize`（默认 20）；响应体为 `PageModel<T>`（字段名 `page` / `pageCount` / `dataCount` / `PageSize` / `data`，注意 `PageSize` 首字母大写是框架现状）。
- **返回体**：一律走 `BaseApiController` 的 `Success<T>()` / `Failed()` / `SuccessPage<T>()` / `Success<string>(null, msg)`，不要自造结构。
- **实体位置**：`MultiAgentDevelop.Model/Models/Sms*.cs`，命名空间必须精确等于 `MultiAgentDevelop.Model.Models`（否则 `DBSeed` 不建表）；集成 `BaseEntity`（注意额外 `using MultiAgentDevelop.Model.Models.RootTkey;`）。
- **主键**：`long`（继承 `BaseEntity` → `RootEntityTkey<long>`），雪花 ID，**禁止改成 `int`**。
- **列名**：自有业务字段用 `[SugarColumn(ColumnName = "snake_case")]` 显式声明；继承自 `BaseEntity` 的公共字段沿用框架默认（列名 = 属性名）。**不改全局列名转换策略**，避免波及既有系统表。
- **长整型传输**：`Id` 等 `long` 字段经 Newtonsoft 序列化为**字符串**，前端 TS 类型写 `string`。
- **权限**：控制器标 `[Authorize(Permissions.Name)]`，并在「菜单权限管理」登记菜单 + 接口权限（步骤见 `docs/prd/02-短信账号管理.md` §8）。
- **加密密钥**：服务端密钥（`AccessSecret` / `AppSecret`）落库前用 `AesHelper.Encrypt` 加密，列表/详情接口只返回掩码。

### 供应商下拉（跨功能公共查询）

账号等功能需要供应商下拉数据时，**不新增供应商控制器**，在本模块控制器暴露只读端点（如 `GET /api/SmsAccount/providerOptions`，返回全部未删除供应商含 `Status` 标记）。供应商的增删改仍归 PRD-01。

## L4-F1 · 短信账号管理

> **实现状态**：后端 T2-1 / 前端 T2-2 已完成（`dotnet build` 零错误），等待 QA 验收；详细契约以 `docs/prd/02-短信账号管理.md` 为准，本节的规则编号与之一致。
> 相关代码：`Model/Models/SmsAccount.cs`、`Model/Models/SmsProvider.cs`（前置）、`Model/ViewModels/SmsAccountDtos.cs`、`Common/Helper/AesHelper.cs`、`IServices/ISmsAccountServices.cs`、`Services/SmsAccountServices.cs`、`Api/Controllers/SmsAccountController.cs`、`Vue3/src/api/smsAccountApi.ts`、`Vue3/src/views/sms/account.vue`。

### 1. 功能概述

管理对接第三方服务商的账号配置（一个供应商下可有多个账号），支持增删改查、启停、连通性测试、余额与预警阈值维护。

### 2. 使用者与场景

- 短信管理员在已配置的供应商下新增账号（如「阿里云账号 A / 账号 B」）。
- 管理员查看各账号剩余额度，为余额不足的账号补充（充值见 F2）。

### 3. 业务流程

新增账号（选择供应商 + 填密钥）→ 测试连通性 → 启用 → 供发送使用。

### 4. 业务规则

| 编号 | 规则 |
| --- | --- |
| R1 | `account_name` 全局唯一（不含已逻辑删除数据），新增/修改时校验，重复提示「账号名称已存在」 |
| R2 | 必须绑定一个**存在且未删除**的 `sms_provider`（`provider_id`）；绑定禁用供应商时提示告警但允许保存（AI建议） |
| R3 | `access_secret` 落库前 AES 加密（密钥取现有配置），列表/详情接口返回掩码 `******`；编辑时留空 = 不修改 |
| R4 | 逻辑删除 `is_deleted=1`，不物理删除；列表、唯一性校验均过滤已删除数据 |
| R5 | 被 `sms_recharge` 或 `sms_send_record` 引用的账号禁止删除，提示「该账号已有充值/发送记录，不可删除」（AI建议，与 PRD-01 R5 同构） |
| R6 | 将状态由禁用改为启用时，校验必填接入参数（`access_key` / `access_secret` / `provider_id`）完整，否则提示「接入参数不完整，无法启用」 |
| R7 | 余额低于等于 `warn_threshold` 且 `warn_threshold > 0` 时，列表页此行标黄并给出预警图标；`warn_threshold = 0` 表示不预警 |
| R8 | 禁用账号不得用于发送（发送链路后续版本实现，本功能阶段仅管理） |

### 5. 接口清单

路由前缀 `api/SmsAccount`，统一 `MessageModel<T>` 返回。**已按 PRD-02 实现**，共 8 个端点。

| 接口 | 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- | --- |
| 分页查询 | GET | `/api/SmsAccount/page?page=1&intPageSize=20&accountName=&providerId=&status=` | accountName 模糊 / providerId / status（空=全部） | `PageModel<SmsAccountDto>` |
| 详情 | GET | `/api/SmsAccount/detail/{id}` | — | 账号 DTO，`AccessSecret` 为掩码 |
| 新增 | POST | `/api/SmsAccount/create` | 账号表单 DTO | 新账号 id（`long` → 字符串） |
| 修改 | PUT | `/api/SmsAccount/update` | 含 `Id` 的表单 DTO；`AccessSecret` 留空 = 不修改 | — |
| 删除 | DELETE | `/api/SmsAccount/remove/{id}` | — | — ，受 R5 保护 |
| 启用/禁用 | PATCH | `/api/SmsAccount/status/{id}/{status}` | status=true/false | — |
| 连通性测试 | POST | `/api/SmsAccount/test/{id}` | — | `{Success, Balance, Message}` |
| 供应商下拉 | GET | `/api/SmsAccount/providerOptions` | — | `List<SmsProviderOptionDto>` |

> 路径风格与 PRD-01 的 `api/SmsProvider` 对齐（分页 `/page`、启停 `PATCH /status/{id}/{status}`、测试 `POST /test/{id}`），但**动作段不能省**，理由见 F0。

### 6. 异常/边界

- 账号名称重复 → `Failed("账号名称已存在")`。
- 绑定的供应商不存在或已删除 → `Failed("绑定的供应商不存在")`。
- 账号不存在（含已逻辑删除）→ `Failed("账号不存在")`。
- 编辑时传了空 `accessSecret` → 保留原密文，不做覆盖。
- 删除被引用账号 → `Failed("该账号已有充值/发送记录，不可删除")`。

### 7. 依赖钩子

| 项 | 内容 |
| --- | --- |
| 依赖功能 | 供应商管理（PRD-01，读 `sms_provider`） |
| 被依赖 | F2 充值、F3 记录 |
| 共享数据 | `sms_account`（定义见 L1 §2） |
| 事务边界 | 单表操作，无需事务 |
| 横切遵循 | 权限校验、审计字段、逻辑删除、AES 加密、统一返回结构 |

## L4-F2 · 短信充值

### 1. 功能概述

向短信账号增加额度，记录充值流水，保证余额一致。

### 2. 使用者与场景

- 短信管理员为账号补充额度。

### 3. 业务流程

选择账号 → 输入充值额度 → 校验 → 更新余额 + 写流水（同一事务）。

### 4. 业务规则

| 编号 | 规则 |
| --- | --- |
| R1 | 充值必须记录 `balance_before` / `balance_after`（AI建议） |
| R2 | 并发充值时用行锁（`SELECT ... FOR UPDATE`）（AI建议） |
| R3 | `recharge_no` 唯一，防重复提交 |
| R4 | 充值数量必须 > 0（AI建议） |
| R5 | 账号不存在或已逻辑删除不允许充值 |
| R6 | 账号被禁用时是否允许充值：**允许**（充值与启停解耦），但列表给出禁用标签（AI建议） |

### 5. 接口清单

路由前缀 `api/SmsRecharge`。

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 分页查询充值记录 | GET | `/api/SmsRecharge/page?page=1&intPageSize=20&accountId=&beginTime=&endTime=` | 支持账号、时间区间筛选 |
| 充值 | POST | `/api/SmsRecharge` | 前置校验 + 事务（余额更新 + 流水写入） |
| 导出（AI建议） | GET | `/api/SmsRecharge/export` | 按当前筛选条件导出 CSV |

### 6. 异常/边界

- 重复单号 → `Failed("充值单号重复")`。
- 账号不存在/已删除 → `Failed("账号不存在")`。
- 充值数量 ≤ 0 → 前端表单校验拦截，后端二次校验。
- 余额溢出（极小概率）→ 报错并回滚。

### 7. 依赖钩子

| 项 | 内容 |
| --- | --- |
| 依赖功能 | F1 账号管理 |
| 被依赖 | 无 |
| 共享数据 | `sms_account.balance`、`sms_recharge`（定义见 L1 §2、§3） |
| 事务边界 | 余额更新 + 流水写入必须同一事务（`Db.Ado.UseTranAsync` 或 `IUnitOfWorkManage`） |
| 横切遵循 | 权限校验、审计字段、统一返回结构 |

## L4-F3 · 短信记录

### 1. 功能概述

查询所有短信发送明细，支持多条件筛选、状态追踪、导出。

### 2. 使用者与场景

- 管理员排查发送失败问题。
- 普通用户查看自己的发送记录。

### 3. 业务流程

发送短信 → 落记录（`send_status=发送中`）→ 通道回调/轮询更新状态 → 用户查询。

### 4. 业务规则

| 编号 | 规则 |
| --- | --- |
| R1 | 仅能查看自己权限范围内账号的记录（AI建议） |
| R2 | 记录只读，不可删改（审计要求） |
| R3 | 支持按手机号 / 状态 / 时间段 / 账号筛选（AI建议） |
| R4 | 发送失败必须记录 `error_msg` |
| R5 | 手机号在列表页做脱敏展示（`138****8888`），导出保留完整号码（AI建议） |

### 5. 接口清单

路由前缀 `api/SmsRecord`。

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 分页查询 | GET | `/api/SmsRecord/page?page=1&intPageSize=20&phone=&sendStatus=&accountId=&beginTime=&endTime=` | 多条件筛选 |
| 详情 | GET | `/api/SmsRecord/{id}` | — |
| 导出 CSV（AI建议） | GET | `/api/SmsRecord/export` | 大数据量时异步生成 + 下载 |
| 重发（AI建议） | POST | `/api/SmsRecord/resend/{id}` | 仅失败记录可重发 |
| 状态回调（AI建议） | POST | `/api/SmsRecord/callback` | 第三方状态回推，需验签 |

### 6. 异常/边界

- 大批量导出 → 异步生成 + 下载（AI建议）。
- 状态回调需验签，验签失败返回 `Failed("签名校验失败")`。
- 无权限查询他人记录 → 权限过滤器拦截。

### 7. 依赖钩子

| 项 | 内容 |
| --- | --- |
| 依赖功能 | F1 账号管理 |
| 被依赖 | F5 统计报表 |
| 共享数据 | `sms_send_record`（定义见 L1 §4） |
| 事务边界 | 额度扣减 + 记录创建同事务；调用第三方为不可回滚操作，需补偿/对账 |
| 横切遵循 | 权限校验、审计字段、统一返回结构、导出脱敏 |
