# 短信平台 · L1 数据字典

> 全量数据定义集中在此处，各功能文档不再重复定义，避免冲突。
> 落库口径已按 MultiAgentDevelop 框架实际校正（2026-10-13）。

## 0. 全局约定

- **数据库**：Oracle（连接串见 `MultiAgentDevelop.Api/appsettings.json` → `DBS.Main`）
- **ORM**：SqlSugar 5.1.4.158，CodeFirst 建表
- **主键**：`long`（继承 `RootEntityTkey<long>`），**非自增、无序列**，由雪花算法生成
  - 机制：`SqlsugarSetup` 中 `StaticConfig.CustomSnowFlakeFunc = IdGeneratorUtility.NextId`
  - ⚠️ `SqlsugarSetup` 的 `EntityService` 里只对 **`int` 主键**设 `IsIdentity = true`。所以业务表主键**必须用 `long`**——用 `int` 会变成数据库自增，与雪花 ID 冲突。
- **表名**：`[SugarTable("sms_account", "短信账号表")]` 显式声明，snake_case 全小写
- **列名**：自有业务字段用 `[SugarColumn(ColumnName = "account_name", ...)]` 显式声明 snake_case；**继承自 `BaseEntity` 的公共字段沿用框架默认**（列名 = 属性名，Oracle 中即 `Id` / `CreateTime` / `IsDeleted` …）
  > 为什么不把公共字段也改成 snake_case：`BaseEntity` 是既有系统表共用的基类，其列名由 SqlSugar 默认规则决定。要统一改必须动 `SqlsugarSetup` 的全局 `EntityService`，会波及 `Role` / `Modules` / `Permission` 等既有表。**短信平台新增表只对自有字段显式声明**，公共字段保持默认，零风险。
- **布尔类型**：C# `bool`，Oracle 侧 `NUMBER(1)`（false = 0 / true = 1）。实体现有 `Status` / `Enabled` / `IsDeleted` 均如此，**不要用 `int`**。

### 审计与公共字段（继承 `BaseEntity` 自动获得，全表统一）

| C# 属性 | 列名（框架默认 = 属性名） | 类型 | 说明 |
| --- | --- | --- | --- |
| Id | Id | NUMBER(20) | 主键，雪花 ID，非自增 |
| Enabled | Enabled | NUMBER(1) | 是否启用，默认 1 |
| IsDeleted | IsDeleted | NUMBER(1) | 逻辑删除，默认 0 |
| IsInternal | IsInternal | NUMBER(1) | 是否内置数据 |
| CreateId | CreateId | NUMBER(20) | 创建人 ID |
| CreateBy | CreateBy | VARCHAR2(50) | 创建人 |
| CreateTime | CreateTime | DATE | 创建时间，插入时自动补 |
| ModifyId | ModifyId | NUMBER(20) | 修改人 ID |
| ModifyBy | ModifyBy | VARCHAR2(50) | 修改人 |
| ModifyTime | ModifyTime | DATE | 修改时间，更新时自动补 |
| Version | Version | NUMBER(20) | 并发版本号 |

> 1. 继承 `BaseEntity` 的实体，框架查询时**自动过滤** `IsDeleted != true`（详见 L2 §4）。
> 2. 审计字段由 `SqlSugarAop.DataExecuting` 自动填充：`Id` 为 0 时补雪花 ID、`CreateTime` 为空时补当前时间、更新时补 `ModifyTime`；`App.User` 可用时还会补 `CreateId/CreateBy/ModifyId/ModifyBy`。业务代码**不要重复实现**这套逻辑。
> 3. 公共字段的列名沿用框架默认（属性名），只有自有业务字段用 `ColumnName` 声明成 snake_case——详见 §0。

## 5. 枚举集中定义

| 枚举 | 值 | 落库形式 |
| --- | --- | --- |
| provider_type | ALIYUN / TENCENT / MENGWANG / HTTP_CUSTOM | 字符串 |
| status（供应商 / 账号） | true 启用 / false 禁用 | NUMBER(1)（C# bool） |
| send_status | 待发送=0 / 发送中=1 / 成功=2 / 失败=3 | NUMBER(1) |
| recharge_type | 手动=1 / 自动=2 | NUMBER(1) |

> C# 侧一律定义 `enum` 并用 `[SugarColumn]` 映射为上述数值 / 字符串，禁止在业务代码里裸写魔法数字。

## 6. 表关系

- `sms_provider` 1 : N `sms_account`（通过 `provider_id`）
- `sms_account` 1 : N `sms_recharge`（通过 `account_id`）
- `sms_account` 1 : N `sms_send_record`（通过 `account_id`）
- `sms_recharge` / `sms_send_record` 均为流水表，**只增不删**（不做逻辑删除）
- 删除保护：被 `sms_account` 引用的 `sms_provider` 禁止删除（PRD-01 R5）
