## 1. 功能概述

- **功能名称**：短信供应商管理
- **所属菜单**：短信中台 → 短信供应商管理（二级菜单）
- **功能目标**：维护短信中台对接的短信供应商（如阿里云、腾讯云、梦网、自定义 HTTP 通道）的接入参数与启停状态，是账号、充值、发送记录功能的前置基础数据。
- **使用者角色**：系统管理员（全操作）；其他角色默认无权限（通过菜单权限控制）。

## 4. 业务规则

- **R1 唯一性**：`provider_code` 全局唯一（不含已逻辑删除数据），新增/修改时校验，重复提示「供应商编码已存在」。
- **R2 密钥安全**：`app_secret` 落库前 AES 加密（密钥取现有配置），列表/详情接口一律不返回明文（返回掩码 `******`）。
- **R3 启用校验**：将状态从禁用改为启用时，校验必填接入参数（按 providerType 条件必填规则）完整，否则提示「接入参数不完整，无法启用」。
- **R4 连接测试**：「连接测试」按供应商类型发起一次余额查询或鉴权请求，返回 成功(含余额) / 失败(含错误原因)。HTTP_CUSTOM 类型调用 baseUrl + /health。测试不改变任何数据。
- **R5 删除保护**：被短信账号（sms_account）引用的供应商禁止删除，提示「该供应商已被短信账号引用，不可删除」。删除为逻辑删除（is_deleted=1）。
- **R6 逻辑删除**：列表、查询、唯一性校验均过滤 is_deleted=1 的数据。
- **R7 停用影响**：供应商被禁用后，其下账号发送短信时报错「供应商已禁用」（本次仅管理功能，发送链路后续版本实现，验收不涉及）。

## 5. 接口定义

路由前缀 `api/SmsProvider`，遵循项目统一 ApiResponse 结构。

| 接口 | Method | 路由 | 说明 |
|---|---|---|---|
| 分页查询 | GET | `/api/SmsProvider/page?page=1&intPageSize=20&name=&code=&status=` | name/code 模糊，status 空=全部 |
| 详情 | GET | `/api/SmsProvider/{id}` | appSecret 返回掩码 |
| 新增 | POST | `/api/SmsProvider` | Body=表单 DTO |
| 修改 | PUT | `/api/SmsProvider` | Body 含 id；providerCode 忽略 |
| 删除 | DELETE | `/api/SmsProvider/{id}` | 逻辑删除，受 R5 保护 |
| 启用/禁用 | PATCH | `/api/SmsProvider/status/{id}/{status}` | status=1/0 |
| 连接测试 | POST | `/api/SmsProvider/test/{id}` | 见 R4 |

请求示例（新增）：

```json
{
  "providerCode": "ALIYUN",
  "providerName": "阿里云短信",
  "providerType": "ALIYUN",
  "appId": "LTAI5t****",
  "appSecret": "******",
  "signName": "健康体检",
  "dailyLimit": 100000,
  "status": 1,
  "remark": "主力通道"
}
```

## 7. 验收标准（QA 逐条核对）

- [ ] 菜单出现「短信中台 → 短信供应商管理」，使用管理员账号可见可点
- [ ] 新增供应商：必填项不填时有前端校验提示；编码非法字符被拦截
- [ ] 新增成功后列表可查到；编码重复时报「供应商编码已存在」
- [ ] 编辑时编码只读；appSecret 显示掩码，留空保存后原密钥仍有效（可通过连接测试验证）
- [ ] 列表按名称/编码模糊查询、状态筛选结果正确
- [ ] 禁用状态的数据行「启用」操作成功；接入参数不完整时启用被拦截并提示
- [ ] 连接测试返回成功或明确的失败原因
- [ ] 删除后列表不再显示；被账号引用的供应商删除被拦截（本功能阶段无账号数据，可用造数验证）
- [ ] 分页切换正常；接口分页参数生效
- [ ] `dotnet build` 零错误；新增单元测试通过

## 8. 不做清单

- 不做真实发送短信链路（后续版本）
- 不做供应商自动同步/轮询余额（仅手动「连接测试」）
- 不做操作日志（复用全局操作日志中间件，不单独开发）
- 不做 Excel 导入导出（后续按需补充）
