| 项 | 内容 |

## 1. 功能概述

- **功能名称**：短信账号管理
- **所属菜单**：短信中台 → 短信账号管理（二级菜单）
- **功能目标**：维护「供应商下的具体接入账号」（同一供应商可配置多个账号，各自持有独立的 AccessKey / 签名 / 余额），为后续充值（F2）与发送记录（F3）提供账号主体。
- **使用者角色**：系统管理员（全操作）；其他角色默认无权限（通过菜单权限控制）。

## 4. 业务规则

- **R1 唯一性**：`account_name` 全局唯一（不含已逻辑删除数据），新增/修改时校验，重复提示「账号名称已存在」。
- **R2 供应商绑定**：`provider_id` 必填且必须指向存在、未删除的供应商；绑定的供应商为**禁用**状态时允许保存，但列表行给出「供应商已禁用」告警标签。
- **R3 密钥安全**：`access_secret` 落库前 AES 加密（密钥取配置 `Sms:SecretKey`）；列表、详情接口一律返回掩码 `******`，编辑时留空即不覆盖原密文。
- **R4 逻辑删除**：删除为逻辑删除（`is_deleted=1`）；列表、查询、唯一性校验均过滤已删除数据。
- **R5 删除保护**：被 `sms_recharge`（充值流水）或 `sms_send_record`（发送记录）引用的账号禁止删除，提示「该账号已有充值/发送记录，不可删除」。**本阶段两张流水表尚未建表，删除前会先判断表是否存在，不存在则跳过检查**；表建好后该保护自动生效（造数即可验证）。
- **R6 启用校验**：将状态由禁用改为启用时，校验 `provider_id` / `access_key` / `access_secret` 完整，否则提示「接入参数不完整，无法启用」。
- **R7 余额预警**：`warn_threshold > 0` 且 `balance <= warn_threshold` 时，列表行标黄 + 预警图标；`warn_threshold = 0` 表示不预警。
- **R8 连通性测试**：按账号绑定的供应商类型发起一次鉴权/余额查询，返回「成功（含余额）/ 失败（含原因）」。**测试不改变任何数据**；供应商未配置真实通道时返回明确的失败原因（如「供应商类型 HTTP_CUSTOM 未配置 baseUrl」）。
- **R9 禁用影响**：账号被禁用后不得用于发送（发送链路后续版本实现，本功能阶段仅管理，验收不涉及）。

## 5. 接口定义

路由前缀 `api/SmsAccount`，统一 `MessageModel<T>` / `PageModel<T>` 返回结构（见 L2）。

> **为什么集合级动作也带路径段**：框架的「菜单同步」（`PermissionController.MigratePermission`）只登记 swagger 中形如 `/api/xxx/...`（控制器名后必须还有一段）的接口，裸 `/api/SmsAccount` 会被漏掉，导致非超级管理员角色鉴权失败。故新增/修改也带 `create`/`update` 段。

| 接口 | Method | 路由 | 说明 |
|---|---|---|---|
| 分页查询 | GET | `/api/SmsAccount/page?page=1&intPageSize=20&accountName=&providerId=&status=` | accountName 模糊；providerId/status 空 = 全部 |
| 详情 | GET | `/api/SmsAccount/detail/{id}` | accessSecret 返回掩码 |
| 新增 | POST | `/api/SmsAccount/create` | Body = 表单 DTO，返回新账号 id（字符串） |
| 修改 | PUT | `/api/SmsAccount/update` | Body 含 id；accessSecret 空 = 不修改 |
| 删除 | DELETE | `/api/SmsAccount/remove/{id}` | 逻辑删除，受 R5 保护 |
| 启用/禁用 | PATCH | `/api/SmsAccount/status/{id}/{status}` | status = 1/0 |
| 连通性测试 | POST | `/api/SmsAccount/test/{id}` | 见 R8 |
| 供应商下拉 | GET | `/api/SmsAccount/providerOptions` | 返回**全部未删除**的供应商 `{Id, ProviderName, ProviderType, Status}`（含禁用，前端加「（已禁用）」后缀） |

请求示例（新增）：

```json
{
  "accountName": "aliyun-main",
  "providerId": "1850000000000000001",
  "accessKey": "LTAI5t****",
  "accessSecret": "abcdef123456",
  "signName": "健康体检",
  "balance": 10000,
  "warnThreshold": 1000,
  "status": true,
  "remark": "主力账号"
}
```

> `providerId` / `id` 为 `long`，Newtonsoft 全局配置会把 Int64 序列化为**字符串**，因此前端 TS 类型一律写 `string`。

## 6. 数据库设计（Oracle）

表名：`sms_account`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | NUMBER(20) PK | 主键，雪花 ID，非自增 |
| account_name | VARCHAR2(64) NOT NULL | 唯一（应用层校验） |
| provider_id | NUMBER(20) NOT NULL | 关联 `sms_provider.id` |
| access_key | VARCHAR2(128) | |
| access_secret | VARCHAR2(500) | AES 密文 |
| sign_name | VARCHAR2(64) | |
| balance | NUMBER(12,2) DEFAULT 0 | 剩余额度 |
| warn_threshold | NUMBER(12,2) DEFAULT 0 | 预警阈值，0 = 不预警 |
| status | NUMBER(1) DEFAULT 1 | bool：true 启用 / false 禁用 |
| remark | VARCHAR2(255) | |
| 审计字段 | — | `Id` / `CreateId` / `CreateBy` / `CreateTime` / `ModifyId` / `ModifyBy` / `ModifyTime` / `Enabled` / `IsDeleted` / `IsInternal` / `Version`，继承 `BaseEntity` |

实体：`MultiAgentDevelop.Model/Models/SmsAccount.cs`，`[SugarTable("sms_account", "短信账号表")]`，继承 `BaseEntity`，主键 `long`。

**列名口径**：自有业务字段用 `[SugarColumn(ColumnName = "snake_case")]` 显式声明；继承自 `BaseEntity` 的公共字段沿用框架默认（列名 = 属性名），**不修改全局列名转换策略**，避免波及既有系统表。

**前置依赖**：本功能需要 `sms_provider` 表，因此同步提供实体 `MultiAgentDevelop.Model/Models/SmsProvider.cs`（表结构见 PRD-01 §6）。供应商的**管理功能**（Controller/Service/UI）仍属 T1，不在本 PRD 范围。

## 7. 验收标准（QA 逐条核对）

- [ ] 新增成功后列表可查到；`balance` 显示初始额度
- [ ] 编辑弹窗中 `accessSecret` 显示掩码，留空保存后原密钥仍有效（通过连通测试验证）

## 8. 菜单与权限注册（DEV 完成，运维/管理员执行）

> 当前 `appsettings.json` 的 `SeedDBDataEnabled=false`，且线上库已存在菜单数据，**改种子 tsv 不会生效**。按以下步骤在运行中的系统里注册（与 PRD-01 同一套流程）。

1. **注册接口权限**（菜单权限管理 → 接口管理 → 新增）：
   - 名称：`短信账号管理接口`
   - 链接地址（LinkUrl）：`/api/smsaccount.*`（正则，一条即可覆盖本控制器全部接口）
   - 启用：是
2. **注册菜单**（菜单权限管理 → 菜单管理 → 新增）：
   - 一级：`短信中台`（若无）→ 二级：`短信账号管理`，路径 `Code = /sms/account`，图标自选
   - 在 `短信账号管理` 下新增 6 个按钮（`IsButton=1`）：
     | 名称 | Func |
     |---|---|
     | 查询 | `handleQuery` |
     | 新增 | `handleAdd` |
     | 编辑 | `handleEdit` |
     | 删除 | `handleDel` |
     | 启用/禁用 | `handleStatus` |
     | 连通测试 | `handleTest` |
3. **分配权限**（菜单权限管理 → 权限分配）：把上述菜单与按钮、接口权限分配给目标角色并保存。
4. 重新登录（菜单是登录时拉取并生成动态路由的）。

> 前端页面路径规则：菜单 `path` 去掉开头 `/`，映射到 `src/views/<path>.vue`。因此 `Code=/sms/account` 对应 `MultiAgentDevelop.Vue3/src/views/sms/account.vue`。

## 9. 不做清单

- 不做真实短信发送链路（后续版本）
- 不做账号粒度的日限额（日上限在供应商上，见 PRD-01）
- 不做供应商的新增/编辑/删除（属 PRD-01 / T1）
- 不做余额自动同步（仅手动「连通测试」触发一次查询，不落库）
- 不做操作日志（复用全局操作日志中间件，不单独开发）
- 不做 Excel 导入导出（后续按需补充）
